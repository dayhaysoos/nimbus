There seems to be so many regressions. can you fix these? • The patch introduces at least two state-management regressions in review recovery/finalization, and the new SSE abort
  wiring can cancel startup after partial setup work. Those issues can lose valid review results or make the new fail/start
  flows unreliable.

  Full review comments:

  - [P1] Allow stale-recovered attempts to finalize successfully — /Users/nickdejesus/Code/nimbus/packages/worker/src/lib/
    review-runner/finalization.ts:27-29
    When handleGetReview() auto-recovers a stale running review, recoverStaleRunningReviewIfNeeded() moves it to queued with
    error_code='retry_scheduled' before the original worker is fenced. If that original attempt finishes successfully a
    moment later, this new guard drops the report because the row is no longer running, so the valid result is lost and the
    queued retry proceeds anyway.
  - [P1] Fence manual fail against later retry scheduling — /Users/nickdejesus/Code/nimbus/packages/worker/src/api/reviews/
    recovery.ts:297-302
    This new running-state fail path only flips the review row to failed. The worker loop still calls scheduleReviewRetry()
    on later transient errors without checking for review_execution_aborted, so a user who clicks “Fail review” on a stuck
    run can have it bounce back to queued as soon as the in-flight attempt later hits a retryable provider/db/network
    failure. Manual fail needs to fence or abort the current attempt before it can reschedule itself.
  - [P2] Don't cancel startup when the SSE client disconnects — /Users/nickdejesus/Code/nimbus/packages/cli/src/app/reviews/
    ui-proxy.ts:196-199
    Aborting the /start/events flow on response.close now feeds an AbortSignal into startStudioNewReview(), and
    resolveReviewContext() treats that as fatal before review creation. If the browser tab is closed or the SSE drops during
    checkpoint/workspace/deployment setup, the flow exits with AbortError after some setup work has already succeeded, but
    before a review ID exists, leaving unattached startup artifacts and forcing the user to rerun the whole start flow.
