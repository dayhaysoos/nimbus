# Nimbus Review Studio Rebuild: Slice 1 Launch Experience

## Summary
Before any implementation work, create and switch to a fresh branch from `main`. Default branch name: `codex/studio-launch-rebuild` unless you rename it before coding starts.

Slice 1 rebuilds Nimbus Studio around one page only: the current-state launch experience at `/`. This page is not a dashboard and not a history browser. Its only responsibility is to resolve the current repo/branch/`HEAD`, determine whether the current commit is launchable, and either:

- immediately route into the existing session for that commit, or
- present a minimal launch surface for starting a new session, or
- clearly explain why launch is blocked

This slice should remove the old broad Studio/history/report route structure aggressively rather than preserving it as product UI.

## Key Changes
### Branch and implementation start
- Create a fresh branch from `main` before touching code.
- Use `codex/studio-launch-rebuild` as the default branch name.
- Do not implement on top of the current checked-out branch directly.

### Product behavior for `/`
- Make `/` a current-state resolver, not a home screen.
- Load current repo/branch context and preflight for `HEAD`.
- Query current branch sessions and detect whether one already exists for `preflight.commitSha`.
- If a matching session exists, immediately `replace`-route to `/sessions/:sessionId`.
- If no matching session exists:
  - show a startable launch card for `intent_aware` mode
  - show the same launch card in downgraded `basic` mode when Entire is unavailable
  - show a blocked state when review cannot start
- Launching a review uses the existing start SSE flow and routes to the returned `routePath` on completion.

### Reused contracts and interfaces
No backend or CLI contract changes are required for slice 1. Reuse these as-is:
- Studio context and preflight
- Studio start action and start-event stream
- review session list lookup for current repo/branch
- canonical session route returned by the start contract

UI-facing route and interface expectations for slice 1:
- `/` becomes the primary launch resolver
- `/sessions/:sessionId` remains the primary session destination
- older broad routes/components are removed or replaced in this slice rather than kept as first-class UI

### Launch page UX spec
- Single-column layout, narrow operator-console feel, no app shell nav.
- Top facts row: repo, branch, current commit.
- Main state card:
  - `Checking current state`
  - `Ready to review`
  - `Starting review`
  - `Basic mode fallback`
  - `Blocked`
- Secondary facts card:
  - checkpoint target result
  - Entire context result
  - explicit fallback note when in `basic`
  - learn-more link for Entire
- Primary CTA when startable and no existing session: `Start review session`
- No history list, report links, pass summaries, policy controls, or artifact navigation on this page.

### Copy and visual direction
- Tone: plainspoken, operational, honest.
- Use `adopt` terminology nowhere on this page unless an existing session is found and routed away; adoption belongs to later slices.
- Visual direction: minimal, deliberate, technical, with IBM Plex Sans for UI/body and JetBrains Mono for labels, IDs, and state rows.
- Color system: neutral shell, green for ready, amber for `basic`, red for blocked/error.
- Motion: restrained only.
  - small page settle on load
  - small card/state transitions
  - live stage rows appear only when real launch events arrive
  - respect `prefers-reduced-motion`

## Implementation Notes
- Keep the current backend truth model: session-first, current `HEAD` only, no silent mutation of current checkout.
- Treat “existing session for current commit” as `anchorCommitSha === preflight.commitSha` on the current repo/branch session list.
- If repo/branch context changes during launch, fail visibly and force fresh resolution instead of continuing optimistically.
- For `basic` mode, launch must remain fully enabled; the downgrade is explanatory, not blocking.
- Remove old route structures/components aggressively in the same implementation slice so the new shape is the actual product, not a thin layer over the previous IA.

## Test Plan
- Repo context detected, no existing session, `intent_aware` preflight:
  - launch page renders
  - start CTA enabled
  - start stream shows bounded stage progress
  - completion routes to returned session path
- Repo context detected, no checkpoint / no Entire context:
  - page shows `basic` fallback state
  - Entire learn-more link present
  - start CTA still enabled
- Repo context detected, matching session already exists for current commit:
  - `/` immediately replace-routes into that session
  - no alternate “new review” path is presented first
- Preflight blocked:
  - no start CTA
  - blocking reason shown clearly
- Repo/branch drift while launch stream is active:
  - launch aborts with visible context-changed error
  - user must retry from fresh current state
- Reduced motion enabled:
  - no non-essential animated transitions
- Removed legacy route shape:
  - app no longer presents old history/report-first Studio surfaces as active product UI

## Assumptions
- Implementation starts from `main`, not from an older redesign branch checkout.
- Default branch name is `codex/studio-launch-rebuild`.
- No new backend endpoint is needed for slice 1; client-side matching of current commit to current-branch sessions is acceptable.
- Session page, reviewed diff, adopt, and merge-back experiences are intentionally deferred to later slices except for preserving `/sessions/:sessionId` as the destination.
